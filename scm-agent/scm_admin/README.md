# scm_admin —— 审批看板

Flask 写的**单页只读**看板（默认 `:5000`）：审批明细 + 一次通过率。
它自己**不存数据**，读的是平台服务 Store 里 `approval` 命名空间的审批记录
（由 `scm_agent/src/integrations/idempotency.py::record_approval` 写入）。

没有登录、没有写接口。审批动作发生在演示工作台（interrupt → 人工决策那一步），
看板是事后审计的视角：谁批的、第几轮批的、有没有返工。

## 起法

必须先起平台服务，再起看板：

```bash
cd ../scm_agent && ./run_scm_agent     # 平台服务，:2024
cd ../scm_admin && ./run_scm_admin     # 本看板，:5000
```

打开 <http://127.0.0.1:5000>。**先在工作台上跑一笔需要审批的场景**
（如「采购申请（新供应商转人工审批）」「收货验收（不良率超阈值复核）」），
做出批准 / 驳回 / 改判重报，看板上就有内容了。

> 只想看智能体本身的话不用起这个：仓库根目录 `python quickstart.py` 离线就能跑通
> 全部链路，演示工作台在平台服务里（`/scm/workbench/`）。

## 页面

| 路径 | 内容 |
|---|---|
| `/` | 审批看板（单页） |
| `/api/approvals` | 全部审批记录 + 顶部统计（JSON） |

## 口径

* **一次通过** = 第 0 轮（`revision == 0`）的结论就是「通过」。改判重报不算 ——
  那一单是被退回来改了才继续走的。
* **一次通过率** = 一次通过数 ÷ 申请总数，两边都只数第 0 轮（第二轮不重复计数）。
* **返工次数** = 同一申请在第 1 轮及以后出现的审批记录条数。

审批记录是**每轮一行**（键 `线程:方案[:r轮次]`，同一轮内首写胜 —— 节点重放不会
记第二笔），所以「多轮」在这里是可数的；这也是这张看板只能读到平台 Store
而不做本地缓存的原因：轮次是聚合的输入，不能先折叠掉。

## 配置（`.env`）

| 变量 | 说明 |
|---|---|
| `SCM_SERVER_URL` | 平台服务地址，默认 `http://127.0.0.1:2024` |
| `SCM_USER_ID` / `SCM_PASSWORD` | 换令牌用：看板拿它 POST `{SCM_SERVER_URL}/scm/get_token`。**必须与 `scm_agent` 的 `DEMO_USER_ID` / `DEMO_USER_PASSWORD` 一致**，否则换不到令牌、页面直接提示原因 |
| `SCM_ADMIN_PORT` | 看板端口，默认 `5000` |

复制 `.env.example` 为 `.env` 后填写（平台服务没起时页面会直接说明，而不是白屏）。

## 文件

| 文件 | 作用 |
|---|---|
| `scm_admin_app.py` | Flask 应用：`/` 页面、`/api/approvals` 数据、`summarize()` 聚合口径 |
| `templates/approvals.html` | 单页（自带样式与脚本，不引任何前端框架） |
| `scm_store_api/scm_store_api.py` | 平台 Store 的**只读**客户端（目前只有审批记录一个入口） |
